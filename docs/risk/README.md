# リスク管理 概要

## 目的

本ドキュメントは、開発プロジェクトにおけるリスク管理の概要と関連ドキュメントの構成を示します。ISO 27001（情報セキュリティ）および ISO 9001（品質マネジメント）の要求事項に準拠し、組織的かつ継続的なリスク管理を実施します。

## リスク管理の基本方針

1. **予防的アプローチ**: リスクを早期に識別し、問題が顕在化する前に対処する。
2. **継続的改善**: リスク管理プロセスを定期的に見直し、有効性を向上させる。
3. **説明責任の明確化**: 各リスクにオーナーを設定し、対応責任を明確にする。
4. **透明性の確保**: リスク情報をステークホルダーと適切に共有する。

## リスクカテゴリ

```
技術リスク     ── セキュリティ、パフォーマンス、可用性、技術的負債
プロジェクトリスク ── スケジュール、リソース、依存関係、品質
ビジネスリスク  ── 規制・法令、競合、市場変化、顧客要件
```

## リスクレベルの概要

| レベル | スコア | 対応方針 |
|---|---|---|
| 重大 | 17-25 | 即時対応・経営層への報告必須 |
| 高 | 10-16 | 優先対応・月次モニタリング |
| 中 | 5-9 | 計画的対応・四半期モニタリング |
| 低 | 1-4 | 受容または定期確認 |

## 関連規格・基準

- ISO 27001:2022 附属書 A（情報セキュリティ管理策）
- ISO 9001:2015 第 6 章（計画）、第 8 章（運用）、第 9 章（パフォーマンス評価）
- NIST Cybersecurity Framework
