# 情報セキュリティマネジメントシステム (ISMS) 概要

## 目的

本ドキュメントは、組織における情報セキュリティマネジメントシステム (ISMS) の全体像を定義し、ISO/IEC 27001 への適合を維持するための枠組みを提供します。ISMS は、情報資産を保護し、機密性・完全性・可用性 (CIA) を確保することを目的とします。

## 適用範囲

本 ISMS は以下の範囲に適用されます。

- 組織が開発・運用するすべてのソフトウェア製品およびサービス
- GitHub 上で管理されるソースコードおよび関連ドキュメント
- クラウドインフラストラクチャ (AWS, GCP, Azure 等)
- SaaS ツール (Linear, Notion, Slack, GitHub 等)
- 社員、契約社員、業務委託先が使用するすべての機器およびアカウント
- 顧客データおよびパートナーデータを処理するすべてのシステム

## ISO/IEC 27001 との対応

本 ISMS は ISO/IEC 27001:2022 に準拠して構築されています。以下に主要な条項と本ドキュメント群の対応関係を示します。

| ISO 27001 条項 | 内容 | 対応ドキュメント |
|--------------|------|----------------|
| 条項 5 (リーダーシップ) | 経営層のコミットメント、方針 | 本 README (セキュリティ方針セクション) |
| 条項 6 (計画) | リスクアセスメント、目的 | リスク管理手順 (別途) |
| 条項 7 (支援) | 資源、力量、認識、コミュニケーション | 本 README (組織・責任セクション) |
| 条項 8 (運用) | 運用の計画・管理 | 各個別ポリシー |
| 条項 9 (パフォーマンス評価) | 監視・測定・内部監査 | 本 README (レビュースケジュールセクション) |
| 条項 10 (改善) | 不適合・是正処置 | インシデント管理手順 (別途) |
| 附属書 A 5 (組織的管理策) | 方針、役割、資産管理 | information-classification.md, access-management.md |
| 附属書 A 6 (人的管理策) | スクリーニング、オフボーディング | access-management.md |
| 附属書 A 8 (技術的管理策) | アクセス制御、暗号化、ログ | access-management.md |

## 情報セキュリティ基本方針

組織は、以下の基本方針に従って情報セキュリティを管理します。

1. **機密性の確保**: 情報は権限を持つ者のみがアクセスできるよう管理する
2. **完全性の維持**: 情報が正確かつ改ざんされていない状態を維持する
3. **可用性の確保**: 必要なときに情報およびシステムへアクセスできる状態を維持する
4. **法令遵守**: 個人情報保護法、不正アクセス禁止法、その他適用法令を遵守する
5. **継続的改善**: セキュリティインシデントおよびリスク評価の結果を反映し、継続的に改善する
6. **教育・訓練**: 全メンバーに対してセキュリティ教育を実施し、セキュリティ意識を向上させる

## 組織と責任

### ISMS 責任者

| 役割 | 責任内容 |
|------|---------|
| ISMS 管理責任者 | ISMS 全体の維持・改善、経営層への報告 |
| セキュリティ担当者 | 日常的なセキュリティ管理、インシデント対応 |
| 各チームリーダー | チーム内のセキュリティポリシー遵守の監督 |
| 全メンバー | ポリシーの遵守、インシデントの報告 |

### エスカレーションフロー

セキュリティインシデントが発生した場合、以下の順序でエスカレーションします。

```
発見者 -> セキュリティ担当者 -> ISMS 管理責任者 -> 経営層
```

インシデントの重大度に応じ、顧客・監督機関への通知が必要な場合があります。

## レビューと監査スケジュール

| 活動 | 頻度 | 担当 |
|------|------|------|
| アクセス権レビュー | 四半期ごと (1/4/7/10 月) | セキュリティ担当者 |
| リスクアセスメント | 年 1 回 (および重大変更時) | ISMS 管理責任者 |
| 内部監査 | 年 1 回 | ISMS 管理責任者 + 外部レビュア |
| 経営層レビュー | 年 1 回 | 経営層 |
| ポリシードキュメントレビュー | 年 1 回 (および重大変更時) | セキュリティ担当者 |
| インシデント振り返り | インシデント発生後 2 週間以内 | セキュリティ担当者 |
