# GitHub Copilot 利用ポリシー

**対象**: 開発チーム全員
**最終更新**: 2026-06-12
**ドキュメントオーナー**: 開発チームリード / 情報セキュリティ担当

---

## 1. 目的

本ポリシーは、GitHub Copilot の適切な利用方法を定め、コード品質・セキュリティ・ライセンスコンプライアンスを維持しながら開発生産性を向上させることを目的とする。

---

## 2. 利用許可範囲

以下の用途での利用を許可する。

| 用途 | 具体例 |
|------|--------|
| コード補完 | ボイラープレートコード、定型的なロジック、繰り返しパターンの補完 |
| テスト生成 | ユニットテスト、スナップショットテストのスケルトン生成 |
| コメント・ドキュメント生成 | 関数のJSDoc / Docstring 生成、インラインコメントの補完 |
| リファクタリング支援 | コードの整形、変数名の提案（採用は自己判断） |
| 学習・調査 | 新しいフレームワークの使い方を手元で試す際の補助 |

---

## 3. 禁止事項

### 3.1 機密アルゴリズムへの適用禁止
以下の領域では Copilot の提案を利用しないこと。

- 自社プロダクトの**コアビジネスロジック**や**独自アルゴリズム**（競合優位性の源泉となるコード）
- 暗号処理・セキュリティ関連の実装（脆弱な実装が生成されるリスクが高い）
- APIキー・シークレット・認証情報を直接扱うコード

### 3.2 ライセンス的にグレーな領域
- オープンソースの特定ライブラリの実装を模倣するコードを生成させる行為
- Duplication Detection を無効化した状態での利用
- GPL等のコピーレフトライセンスが適用されるコードに類似する出力の無確認採用

### 3.3 その他の禁止事項
- 個人アカウントの Copilot を業務コードのリポジトリで使用すること（会社契約のシートを使用すること）
- Copilot Chat に機密情報・個人情報・顧客データを貼り付けること

## 4. Copilot 推奨設定

### 4.1 Duplication Detection（重複検出）の有効化
重複検出機能は必ず有効にすること。これにより、公開リポジトリのコードと一致または類似する提案がフィルタリングされる。

**設定方法（GitHub.com）**
1. GitHub アカウントの Settings を開く
2. Copilot → Policies を選択
3. "Suggestions matching public code" を **Blocked** に設定

**IDE 側の設定（VS Code）**
```json
// .vscode/settings.json または ユーザー設定
{
  "github.copilot.enable": {
    "*": true
  }
}
```

### 4.2 推奨する IDE 拡張設定（VS Code）
- `github.copilot` 拡張をインストールする
- Copilot Chat 拡張も合わせてインストールする
- インライン提案の自動表示は ON のまま運用（必要に応じて個別に OFF 可）

### 4.3 対象外ファイルの設定
`.env` ファイルや機密設定ファイルを Copilot の参照対象から除外するため、`.gitignore` と合わせて適切に管理すること。

## 5. 生成コードのレビュー必須事項

Copilot が提案したコードは、以下の観点で**必ずレビュー**してから採用すること。

### 5.1 セキュリティ確認
- SQLインジェクション、XSS、CSRF 等の脆弱性が含まれていないか
- 認証・認可の処理が適切か
- シークレット・パスワードがハードコードされていないか

### 5.2 正確性・品質確認
- 提案されたコードが実際に意図した動作をするか、手動でトレースする
- エラーハンドリングが適切に実装されているか
- 存在しない関数やAPIが使われていないか（ハルシネーション確認）

### 5.3 コーディング規約との整合性
- プロジェクトのコーディングガイドラインに準拠しているか
- 命名規則が統一されているか
- 既存コードのスタイルと一致しているか

### 5.4 テスト
- 生成されたコードに対応するテストが存在するか（または生成されたテストが正しいか）
- エッジケースが考慮されているか

## 6. ライセンス上の注意点

### 6.1 Copilot のライセンスポリシー
- GitHub Copilot は公開リポジトリのコードを学習しているが、生成物の著作権についてはグレーゾーンが存在する
- Duplication Detection を有効にすることで、公開コードと一致する提案はブロックされる

### 6.2 採用したコードのライセンス確認
- Copilot の提案が特定の OSS プロジェクトに類似していると感じた場合は、当該プロジェクトのライセンスを確認すること
- GPL / LGPL / AGPL が適用されるコードを採用する場合は、プロダクトへの影響をリードに相談すること

### 6.3 推奨ライセンスカテゴリ
| ライセンス種別 | 採用可否 | 備考 |
|----------------|----------|------|
| MIT / Apache 2.0 / BSD | 原則採用可 | 著作権表示の保持が必要 |
| LGPL | 要確認 | リンク方法によって影響範囲が変わる |
| GPL / AGPL | 原則採用不可 | 採用前にリードに相談 |
| 独自ライセンス | 要確認 | 個別に法務確認 |

## 7. コスト管理（シート数管理）

### 7.1 シート割り当て方針
- シートは開発チームメンバーに限定して割り当てる
- 外部委託メンバー（業務委託・派遣）へのシート付与は事前にリードの承認が必要

### 7.2 利用状況の確認
- 管理者は月次で GitHub Organization の Copilot 利用状況を確認する
- 90日間未使用のシートは解放の対象とする

### 7.3 シートの申請・解放手順
- **追加申請**: リードに Slack で申請 → リードが GitHub Organization の管理画面で割り当て
- **解放**: 退職・プロジェクト離脱時は退職日当日にシートを解放する
- **棚卸し**: 四半期ごとにシート利用者リストを見直す

### 7.4 コスト目安（参考）
| プラン | 月額（USD/シート） |
|--------|-------------------|
| Copilot Individual | $10 |
| Copilot Business | $19 |
| Copilot Enterprise | $39 |

現在の契約プランおよび予算については、リードに確認すること。

## 8. 違反時の対応

本ポリシーに違反した場合、または違反の疑いが生じた場合は、直ちに情報セキュリティ担当に報告すること。詳細は `ai-incident-procedure.md` を参照。
