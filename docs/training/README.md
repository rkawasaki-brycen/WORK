# トレーニングプログラム概要

## 目的

このトレーニングプログラムは、チームの新メンバーが開発ワークフローで使用するツールおよびプロセスを習得することを目的としています。GitHub とプロジェクト管理ツール（Linear）の実践的なスキルを身につけ、チームの標準的な開発サイクルに円滑に参加できるようにします。

## 対象者

- 新規入社のエンジニア
- 他チームからの異動メンバー
- GitHub または Linear の利用経験が少ない開発者

## カリキュラム構成

| # | トレーニング資料 | 内容概要 | 目安時間 |
|---|---|---|---|
| 1 | [GitHub トレーニング](./github-training.md) | リポジトリ管理・PR 作成・コードレビュー・CI/CD・セキュリティ機能 | 4〜6 時間 |
| 2 | [Linear トレーニング](./linear-training.md) | イシュー管理・ワークフロー・スプリント運営・GitHub 連携 | 3〜4 時間 |

## 推奨完了スケジュール

```
入社 1 週目
├── 月曜〜火曜: GitHub トレーニング（資料の通読 + 演習）
└── 水曜〜木曜: Linear トレーニング（資料の通読 + 演習）
    └── 金曜:   不明点の確認 / メンターとの 1on1
```

各トレーニングは「資料の通読」→「演習の実施」→「メンターへの確認」の順で進めてください。

## 修了認定の手順

修了認定は以下の手順で行います。

### ステップ 1: 演習の完了

各トレーニング資料末尾の「演習」セクションを全て実施してください。

### ステップ 2: 演習成果物の提出

以下の成果物を用意してください。

**GitHub トレーニング**
- 演習用ブランチへのリンク（GitHub URL）
- 作成した Pull Request の URL
- コードレビューコメントのスクリーンショット（1 件以上）

**Linear トレーニング**
- 作成したイシューの URL（Linear）
- ステータス変更の履歴が確認できるスクリーンショット
- GitHub PR と連携したイシューの URL

### ステップ 3: メンターによるレビュー

提出物をメンター（オンボーディング担当者）に Slack で共有してください。メンターが確認後、修了認定を行います。

### ステップ 4: 修了記録の更新

メンターが Linear のオンボーディングイシューを `Done` に移動し、修了が記録されます。

## 困ったときは

- **Slack チャンネル**: `#dev-onboarding` で質問してください。
- **メンター**: オンボーディング担当者に直接 DM で相談できます。
- **ドキュメント**: `/docs` 配下に各種ガイドが整備されています。
