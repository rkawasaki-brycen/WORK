# Claude Code トレーニング（開発者向け）

**対象:** 開発チームメンバー全員
**所要時間:** 約60分
**前提知識:** Git の基本操作

---

## 1. Claude Code とは

Claude Code は Anthropic が提供する AI コーディングアシスタントです。ターミナルから直接利用でき、コードベースのコンテキストを理解した上でコード生成・レビュー・リファクタリングを支援します。

### できること

| 機能 | 具体例 |
|------|--------|
| コード生成 | 新機能の実装コード、ボイラープレート、テストコードの作成 |
| リファクタリング | 重複コードの整理、関数分割、可読性の改善 |
| デバッグ支援 | エラーの原因調査、修正案の提示 |
| コードレビュー | 問題点の指摘、改善提案 |
| ドキュメント生成 | コメント、README、API 仕様書の作成支援 |

### 何でないか

- 完璧なコードを保証するツールではありません
- 生成したコードの正確性・安全性の最終責任は**開発者自身**にあります
- 機密情報を渡してよいシステムではありません（詳細は「してはいけないこと」を参照）

## 2. インストールとセットアップ

### 前提条件

- Node.js 18 以上
- npm 9 以上

### インストール手順

```bash
# グローバルインストール
npm install -g @anthropic-ai/claude-code

# バージョン確認
claude --version
```

### 認証設定

```bash
# 認証を開始する（ブラウザが開きます）
claude auth

# 認証状態の確認
claude auth status
```

認証情報は `~/.claude/` に保存されます。このディレクトリ内のファイルを他者に共有したり、リポジトリにコミットしたりしないでください。

### 初回起動確認

```bash
# プロジェクトディレクトリで起動
cd your-project
claude
```

## 3. 基本的な使い方

### 3.1 質問する

コードについて不明な点を尋ねることができます。

```
> このコードの処理の流れを日本語で説明してください
> この関数で発生しうるエラーケースを教えてください
> この実装でパフォーマンス上の問題になりうる箇所はありますか？
```

### 3.2 コードを生成する

```
> ユーザーIDを受け取り、データベースからユーザー情報を取得する関数を実装してください。
  TypeScript で書き、エラーハンドリングを含めてください。

> 上記の関数のユニットテストを Jest で書いてください。
  正常系・異常系（ユーザーが存在しない場合、DB接続エラー）を網羅してください。
```

### 3.3 コードをレビューする

```
> この PR の変更内容をレビューしてください。セキュリティ上の問題に特に注意してください。
> この関数のコードに改善できる点はありますか？
> ESLint のエラーを修正してください
```

### 3.4 コードを説明してもらう

```
> src/auth/middleware.ts の認証ミドルウェアの仕組みを説明してください
> このコードが何をしているか、5歳児にもわかるように説明してください
```

## 4. 効果的なプロンプト技法

### 4.1 コンテキストを明確にする

漠然とした依頼より、背景・制約・ゴールを明示したほうが精度が上がります。

**悪い例:**
```
> ユーザー登録の機能を作って
```

**良い例:**
```
> Node.js + Express + TypeScript の API に、メールアドレスとパスワードでユーザー登録する
  エンドポイント (POST /api/users) を実装してください。
  - パスワードは bcrypt でハッシュ化してください
  - メールアドレスの重複チェックを行い、重複時は 409 を返してください
  - 既存の UserRepository クラス (src/repositories/user.repository.ts) を使ってください
```

### 4.2 段階的に依頼する

一度に大きな機能を依頼するより、小さな単位に分けて依頼するほうが品質が高くなります。

```
Step1: > まずデータモデルの型定義だけを作成してください
Step2: > 次に、その型を使ったリポジトリ層の実装を書いてください
Step3: > 最後に、リポジトリを使ったサービス層を実装してください
```

### 4.3 生成結果を検証するよう依頼する

```
> このコードに脆弱性がないか確認してください
> エッジケース（nullや空文字を渡された場合など）も考慮されていますか？
> このコードのテストカバレッジが低い箇所を指摘してください
```

### 4.4 フォーマットを指定する

```
> この変更の PR 概要を Markdown で書いてください。変更理由・変更内容・テスト方法を含めてください。
> 変更点を箇条書きでまとめてください
> コードコメントを JSDoc 形式で追加してください
```

### 4.5 「なぜ」を聞く

生成されたコードを理解せずに使うのは危険です。必ず理解してから使いましょう。

```
> このコードはなぜこう書くのですか？別の書き方との違いを教えてください
> この実装でセキュリティ面で注意すべき点はありますか？
```

## 5. AI 利用ポリシー（重要）

社内の Claude Code 利用ポリシー（`docs/ai-governance/claude-code-policy.md`）の要点を以下に示します。**利用前に必ず原文を確認してください。**

### 5.1 許可されている用途

- コード生成・リファクタリング・デバッグ支援
- ドキュメント作成
- コードレビュー支援

### 5.2 情報分類別の送信可否

| 情報分類 | AI への送信 | 例 |
|---------|-----------|-----|
| Public | 許可 | オープンソースコード、公開ドキュメント |
| Internal | 原則許可 | 社内設計書、通常の実装コード |
| Confidential | 事前承認が必要 | 非公開アルゴリズム、顧客契約情報 |
| Restricted | 禁止 | APIキー、パスワード、顧客個人情報 |

**Confidential 以上の情報を送信する場合は、AIガバナンス責任者の事前承認を取得してください。**

### 5.3 レビュー責任

- AI が生成したコードであっても、コミット・マージした**開発者が全責任を負います**
- AI 生成コードを含む PR には **`AI-assisted`** ラベルを必ず付与してください
- AI が生成したコードを人間のレビューなしにマージすることは**禁止**されています

### 5.4 利用記録

AI によってコードの大部分が生成された場合、PR 概要に以下の形式で記録してください。

```markdown
## AI 活用状況

- 利用ツール: Claude Code
- 支援内容: ○○機能のリファクタリング、テストコード生成
- レビュー実施: 生成されたコードをすべて確認済み
```

## 6. してはいけないこと

### 絶対に送信してはいけない情報

- **APIキー・パスワード・トークン・秘密鍵**（例: `sk-...`, `AKIA...`）
- **データベース接続文字列**（例: `postgresql://user:pass@host/db`）
- **本番・ステージング環境の認証情報**
- **顧客の個人情報**（氏名・住所・メールアドレス・決済情報など）
- **Restricted または Confidential に分類される情報**

### よくある誤りのパターン

**NG: `.env` ファイルの内容をそのまま貼り付ける**
```
# これをやってはいけない
DATABASE_URL=postgresql://admin:mypassword@prod-db.example.com/app
STRIPE_SECRET_KEY=sk_live_xxxxxxxxxxxx
```

**OK: ダミー値に置き換えてから質問する**
```
> DATABASE_URL=postgresql://user:password@localhost:5432/app
  この接続設定でタイムアウトが頻発しています。設定の改善点を教えてください。
```

**NG: 顧客情報を含むコードをそのまま送る**
```
# これをやってはいけない
customer_email = "tanaka@example.com"
customer_id = "CUST-12345"
```

**OK: ダミーデータに置き換える**
```
> customer_email = "test@example.com"
  customer_id = "CUST-XXXXX"
  この処理を最適化してください
```

### 誤って機密情報を送信してしまった場合

1. 直ちに AIガバナンス責任者に報告する
2. 該当する認証情報は即時ローテーション（パスワード変更・キー失効）する
3. インシデントとして記録する

## 7. CLAUDE.md の設定

`CLAUDE.md` は、リポジトリ固有の Claude Code 設定を定義するファイルです。プロジェクトルートに配置することで、チーム全員が一貫した AI 利用環境を共有できます。

### 記載してよい内容

```markdown
# CLAUDE.md の例

## プロジェクト概要
Node.js + TypeScript + PostgreSQL で構築された REST API

## コーディング規約
- TypeScript の strict モードを使用
- 関数コメントは JSDoc 形式で記述
- テストは Jest + ts-jest を使用

## よく使うコマンド
- `npm run dev` — 開発サーバー起動
- `npm test` — テスト実行
- `npm run lint` — Lint チェック

## ディレクトリ構成
- `src/controllers/` — リクエストハンドラ
- `src/services/` — ビジネスロジック
- `src/repositories/` — DB アクセス層

## AI への指示
- コードは必ず TypeScript で書いてください
- エラーハンドリングを必ず含めてください
- コメントは日本語で書いてください
```

### 絶対に記載してはいけない内容

- APIキー、パスワード、トークン
- 本番・ステージング環境の接続先情報
- 個人情報・顧客情報
- Internal 以上に分類される機密情報

`CLAUDE.md` は Git で管理されます。変更は必ず PR レビューを経て反映してください。

## 8. 実践演習

以下の演習を実際に Claude Code を使って行ってみましょう。

### 演習1: コードの説明

このリポジトリ内の任意のソースファイル（50行以上）を選び、Claude Code に説明を求めてみましょう。

```
> src/[ファイル名] の処理の流れを日本語で説明してください。
  初めてこのコードを読む開発者向けに、重要なポイントを含めて教えてください。
```

確認ポイント:
- [ ] 説明内容がコードと一致しているか
- [ ] 誤った説明がないか自分でコードと照合した

### 演習2: テストコードの生成

既存の関数に対するユニットテストを生成してもらいましょう。

```
> [関数名] のユニットテストを Jest で生成してください。
  正常系・エラー系・境界値ケースを含めてください。
```

確認ポイント:
- [ ] 生成されたテストを実際に実行した（`npm test`）
- [ ] すべてのテストがパスした
- [ ] テストケースに漏れがないか検討した
- [ ] 機密情報がプロンプトに含まれていなかった

### 演習3: PR のコードレビュー

最近マージされた PR を選び、Claude Code にレビューを依頼してみましょう。

```
> 以下の変更内容をレビューしてください。
  セキュリティ・パフォーマンス・コードの可読性の観点で問題点を指摘してください。

  [コードの差分をここに貼り付ける]
```

確認ポイント:
- [ ] 指摘事項が妥当かどうか自分で判断した
- [ ] 誤った指摘（ハルシネーション）がないか確認した
- [ ] 貼り付けたコードに機密情報が含まれていなかった

### 演習4: CLAUDE.md の作成

あなたが担当するプロジェクトの `CLAUDE.md` を作成してみましょう。上記「7. CLAUDE.md の設定」のテンプレートを参考に、実際のプロジェクト情報を記載してください。

確認ポイント:
- [ ] 機密情報が含まれていないことを確認した
- [ ] チームメンバーにレビューを依頼した

## 9. よくある質問（FAQ）

**Q: AI が生成したコードはそのまま使ってよいですか？**
A: いいえ。必ず内容を理解した上で、正確性・安全性・要件との適合性を確認してください。

**Q: AI の提案が間違っていました。どうすればよいですか？**
A: 正しい情報を伝えて再生成を依頼するか、自分で修正してください。AI の誤りを見抜けるよう、コードへの理解を維持することが重要です。

**Q: 使っていいのはコーディングだけですか？**
A: 許可されている用途（コード生成、リファクタリング、デバッグ、ドキュメント生成、コードレビュー支援）であれば問題ありません。業務と無関係な個人的な利用は禁止されています。

**Q: ポリシー違反を見かけたらどうすればよいですか？**
A: AIガバナンス責任者に報告してください。報告者が不利益を受けることはありません。
